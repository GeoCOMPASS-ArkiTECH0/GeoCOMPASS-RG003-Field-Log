# GeCCO KPI–TCI & Implementation Readiness Specification v0.3

**Status:** Phase 0 — Foundational Architecture Refinement  
**Authority:** GeCCO Unified Operational, Curriculum & Administrative Master Specification, reconciled with the latest canonical GeCCO unit register supplied by SecGen Kax'Oxo.  
**Purpose:** Separate competency attainment from operational performance and establish the implementation spine for curriculum, assessment, evidence, KPI measurement, certification, and GAIA-Zer0 workflow execution.

## 1. Governing Architecture

**Descriptor → Target Competency → TCI → Assessment → Evidence → KPI → Certification → Recertification**

### TCI — Target Competency Indicator

A TCI is an observable indicator that demonstrates whether a learner has reached a defined target competency.

TCIs are **not numerical performance targets** and do not replace KPIs.

### KPI — Key Performance Indicator

A KPI is a measurable indicator of the effectiveness, quality, reliability, safety, compliance, or outcome of a competency or operational system over time.

**TCI answers:** Has the required competency been demonstrated?  
**KPI answers:** How well is the competency or resulting system performing?

## 2. Common Competency-to-Certification Model

Every GeCCO unit should use the same implementation sequence:

1. Define the descriptor-derived competency.
2. Define target competencies.
3. Define measurable TCIs.
4. Define assessment methods.
5. Define required evidence.
6. Establish certification thresholds.
7. Establish KPI measurements for continuing performance.
8. Establish recertification requirements.
9. Record authoritative results in the Competency Record.
10. Allow GAIA-Zer0 to route, record, aggregate, notify, and report without redefining standards.

## 6. KPI Record Schema

Every approved KPI should contain:

- KPI ID
- GeCCO Unit
- Descriptor domain
- Metric
- Definition
- Competency relationship
- TCI relationship where applicable
- Evidence/data source
- Measurement frequency
- Target
- Responsible owner
- Escalation threshold
- Review action
- Certification/recertification relevance
- Version
- Approval status
- Effective date
- Approving authority

## 7. Evidence Hierarchy

Evidence should be classified by verification strength:

1. Self-reported evidence
2. Instructor-observed evidence
3. Evaluator-verified evidence
4. Instrument/data-verified evidence
5. Independent or authorized third-party evidence

Certification requirements should specify which evidence class is acceptable for each competency.

## 8. Certification Threshold Model

Certification should not be triggered by a single KPI.

A unit certification decision should evaluate, as applicable:

**Prerequisites + Required knowledge + Practical skills + TCI attainment + Required evidence + Assessment result + Applicable compliance requirements**

KPIs may support continuing performance, recertification, quality assurance, or operational authorization, but should not automatically redefine the competency standard.

## 9. Recertification Model

Each competency should be classified as one or more of:

- One-time qualification
- Periodic maintenance competency
- Recertification competency
- Continuous operational competency

Where periodic or continuous competence is required, applicable KPIs and reassessment requirements should be explicitly linked to the credential.

## 10. Cross-Unit KPI Architecture

A KPI must have one authoritative owner even when multiple units contribute to the outcome.

Distinguish:

- **Unit KPI:** owned by one GeCCO unit.
- **Cross-unit KPI:** depends on multiple GeCCO units but has one designated accountable owner.
- **BioSPHERE System KPI:** measures whole-system performance and should not be duplicated as independent unit KPIs.

## 11. Competency Record Integration

The authoritative Competency Record should connect:

**Candidate → Unit → Competency → TCI → Assessment → Evidence → Result → KPI relationship → Credential**

The same structured information should populate curriculum, assessment, certification, KPI reporting, credential verification, and administrative reporting.

## 12. GAIA-Zer0 Implementation Boundary

GAIA-Zer0 may:

- create and maintain records;
- route candidates through authorized workflows;
- collect and organize evidence;
- calculate approved KPIs;
- generate alerts and reminders;
- aggregate reports;
- track credential status;
- preserve audit trails; and
- recommend administrative actions.

GAIA-Zer0 may not independently:

- redefine competencies;
- redefine TCIs;
- change certification thresholds;
- create institutional policy;
- override evaluator authority; or
- make consequential certification decisions outside authorized policy.

**GeCCO defines the standard. GAIA-Zer0 executes and records the authorized workflow.**

## 14. Implementation Sequence

### Phase 1 — Canonical Data Model

Build the common records:

Candidate; Unit; Competency; TCI; Assessment; Evidence; KPI; Credential.

### Phase 2 — Competency Mapping

For each unit:

Descriptor → Target Competencies → TCIs → Coursework → Assessment → Evidence.

### Phase 3 — Certification Rules

Define prerequisites, thresholds, evaluator authority, exceptions, and recertification rules.

### Phase 4 — KPI Specification

Convert KPI domains into measurable KPI records with approved data sources, frequencies, targets, owners, thresholds, and actions.

### Phase 5 — Administrative Workflow

Implement:

**Enrollment → Training → Assessment → Certification → Review/Recertification**

### Phase 6 — GAIA-Zer0 Integration

Connect the authoritative records and workflows without duplicating data entry or institutional logic.

### Phase 7 — Credential Verification

Implement digital credentialing and controlled verification before physical credential integration.

### Phase 8 — Physical Credential Integration

Add Live PVC Smart ID, QR/NFC, patches, and fulfillment workflows only after the digital system is stable.

### Phase 9 — Agentic Automation

Automate repetitive administrative work only after the underlying workflow and authority boundaries have been validated.

- [ ] KPI data sources are authoritative.
- [ ] KPI ownership is explicit.

- [ ] GAIA-Zer0 executes rather than redefines institutional standards.

## 16. Design Rule

**The descriptor guides the coursework.**  
**The coursework defines the competency.**  
**The TCI demonstrates competency attainment.**  
**The assessment verifies the TCI.**  
**The evidence proves the assessment result.**  
**The KPI measures performance over time.**  
**The credential represents authorized achievement.**  
**GAIA-Zer0 records and administers the authorized workflow.**

This is the implementation spine for GeCCO.
